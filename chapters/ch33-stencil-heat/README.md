# 第 33 章：Stencil、PDE 与热传导

[全书导航](../../README.md) · [原始大纲](../../outline.md) · [上一章](../ch32-fft-frequency/README.md)

本章从一维三点邻域更新走到二维五点热扩散，再把二维更新改为带 Halo 的共享内存分块。[stencil_heat.cu](examples/stencil_heat.cu) 用双缓冲执行固定步数，分别与 CPU 双精度有限差分结果比较，并检查温度范围与两种 GPU 实现的一致性；额外使用 67×51 的非整块网格检验 Halo 边缘。本章在 zyk 用 nvcc 12.8 独立编译并通过 GPU/CPU 对照；单次时间和逐项误差见[验证记录](results/validation.md)，不作为稳定性能结论。

## 1. 方程、离散化与稳定性

热方程 `∂u/∂t = α∇²u` 说明热量由高温处向低温处扩散。网格间距为 `Δx`、时间步长为 `Δt` 时，一维显式 Euler 三点格式为：

```text
r = α Δt / (Δx)^2
u_next[i] = u_old[i] + r (u_old[i-1] - 2u_old[i] + u_old[i+1])
```

二维在 `Δx=Δy` 时采用五点格式：

```text
u_next[y,x] = u_old[y,x] + r (
  u_old[y,x-1] + u_old[y,x+1] + u_old[y-1,x] + u_old[y+1,x]
  - 4u_old[y,x])
```

一维内点可写成 `(1-2r)center+r(left+right)`，为保持非负权重和显式格式的常用稳定条件，需 `0<=r<=1/2`；二维相应是 `(1-4r)center+r(四邻居)`，需 `0<=r<=1/4`。本例均用 `r=0.2`。如果两个轴网格间距不同，令 `rx=αΔt/Δx²`、`ry=αΔt/Δy²`，条件是 `rx+ry<=1/2`，不能把 `r<=1/4` 不加修改地照搬。超过稳定上限时，误差可能逐步增长；短时间内看似平稳不代表稳定。这里说的是此显式离散格式，不是所有 PDE 求解方法的统一上限。

初始条件：一维 128 个格点，中间三分之一为 1，其余为 0；二维 64×48 网格，中间矩形为 1。每一步最外层格点强制为 0，即固定温度的 Dirichlet 边界。它允许热量从边界“流失”，所以总和不应被当成守恒验收条件。真实材料的 `α`、空间单位、时间单位、边界热流和热源项都需要独立建模；本章数值是无量纲教学例子。

## 2. 双缓冲和停止条件

每个时间步的所有新格点必须读取**同一旧时刻**的邻居。若原地覆盖 `old`，一个线程可能读到别的线程刚写的新值，结果与更新顺序有关。代码分配两个同尺寸设备缓冲，kernel 从 `old` 读、向 `next` 写，随后交换指针。CPU 参考也用两组数组、双精度算术。输出每项与 CPU 比较最大绝对差，并检查所有值有限且落在约 `[0,1]`；二维朴素版和分块版再互比。这种比较在 `r=0.2` 和指定尺寸下定义了本章验收条件，不应扩展为所有 PDE 问题的精度保证。

本例停止条件是固定 `100` 个一维步和 `80` 个二维步。若目标是“接近稳态”，应定义例如 `max_i |u_next[i]-u_old[i]| < ε` 的步间变化判据、最大步数及检查间隔；如果目标是模拟到物理时间 `T`，则应选满足稳定条件的 `Δt` 并执行足够步数。只用步间变化判断也可能在极小 `Δt` 下误判；同时检查残差或物理量更可靠。逐步从 GPU 拷贝全场到 CPU 检查会产生很大传输开销，可用设备归约并每隔若干步同步一次。示例只报告固定步数，不声称达到稳态。

## 3. Halo 分块

朴素二维 kernel 每个内点从全局内存读中心与四邻居。16×16 线程块的分块 kernel 先协作加载 18×18 共享内存块：256 个中心位置外加四边一格的 Halo 和角部（角值虽然不用，简化统一装载）。所有线程执行 `__syncthreads()` 后，用共享内存读五点模板。越界 Halo 装入 0；真正的最外层格点仍显式写 0。共享内存数组约 `18*18*4=1296` 字节/块。两个相邻块会重复加载重叠 Halo，这是空间分块的额外工作。

一个时间步结束要完成全网格的更新后，下一步才能读取它。普通 kernel 边界提供全局阶段分隔；不能让同一 kernel 内的不同线程块只靠 `__syncthreads()` 跨时间步同步。时间分块把多步计算留在片上，可以减少内存读写，但每增加一步需要扩大的 Halo、处理边界和线程块间依赖，且有效输出区域变小。实现时间分块前应先验证数值语义，再量测冗余计算、占用率与数据搬运。本例只实现**空间分块**，不把它冒充时间分块。

## 4. 构建、运行与性能记录

在远程仓库根目录：

```bash
cmake -S chapters/ch33-stencil-heat/examples -B build/ch33 \
  -DCMAKE_CUDA_COMPILER=/home/zhangyukai/.local/cuda/bin/nvcc \
  -DCMAKE_CUDA_ARCHITECTURES=120 -DCMAKE_BUILD_TYPE=Release
cmake --build build/ch33 -j
ctest --test-dir build/ch33 --output-on-failure
./build/ch33/stencil_heat
```

预期输出分别列出一维、二维朴素版、二维分块版相对 CPU 的最大误差，二维两版差异、温度范围与各 GPU 循环的 `kernel_time_ms`；二维用 64×48 和 67×51 两种尺寸。全部阈值通过才有末尾 `chapter 33 stencil and heat: PASS`。计时用 CUDA event 围住固定步数的 kernel 循环，不含分配、上传和下载；没有预热或多次统计，因此只是**单次教学记录**，不能据此断言分块必然加速。要做性能结论，应增加网格尺寸、预热、多次重复、同时报告总运行时间和每个格点每步耗时，并检查寄存器、共享内存及访存。较小网格上启动开销可能占主导。

## 5. 常见错误

- 原地更新，混入新旧时间层；或在奇偶步交换后下载了错误缓冲。
- 用 `r=0.3` 做二维等距显式五点格式，还把发散结果归因于 GPU 浮点误差。
- 分块 kernel 某些线程在 `__syncthreads()` 前直接返回，导致块内等待不完整；本例先让全部线程加载并同步，再处理输出越界。
- Halo 装载从负索引或越界读，或只处理内部 tile 而忘记全局边界。
- CPU 参考边界为固定 0，GPU 却用周期/镜像边界；计算“误差”没有比较同一个问题。
- 仅比较最后总和，没有逐点检查或忽略了 Dirichlet 边界下的热量流失。
- 将单次 event 计时误称为稳定性能结果；忽略初始化、传输和按物理时间运行所需步数。

## 6. 练习与参考答案

1. `α=1`、`Δx=1` 时，二维等距显式格式的 `Δt` 最大取多少？答：`r=Δt<=1/4`，工程中通常取更小值留余量；本例取 0.2。
2. `rx=0.2`、`ry=0.25` 是否满足二维稳定条件？答：满足，和为 0.45，未超过 0.5；若改为 `ry=0.35`，和为 0.55，不满足。
3. 为什么 16×16 输出 tile 需要至少 18×18 的输入覆盖？答：五点模板需要各方向一格的 Halo；中心区域每轴 16，加两侧各一格变 18。
4. 若初始 1D 热块完全远离边界，为什么后期全场温度总和会下降？答：外边界固定为 0，热量通过该边界离开所模拟的区域；这不是数值实现必须守恒的封闭系统。
5. 将二维计算改为 `256×192` 网格且保持物理域大小，原 `Δt` 可不变吗？答：通常不能；网格间距缩小约四倍，`r=αΔt/Δx²` 增大约 16 倍。为保稳定，应随 `Δx²` 缩小时间步并重算所需步数。
