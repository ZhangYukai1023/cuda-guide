# 附录 F：实验环境、数据集与性能报告模板

此模板可复制到章节 `results/validation.md` 或一次实验的独立记录。**先记正确性，再记时间。** 原始 stdout/stderr、编译日志、输入/输出文件保留在对应结果目录；表中的数字不得由源码阈值、理论带宽或未运行命令代填。

## F.1 可复现输入卡

```text
案例/版本：例如 ch26 串行单槽 vs 双槽
代码：Git SHA、分支、工作区 diff 是否为空
输入：生成器版本与 seed，或文件路径/每文件 SHA256
形状：batch、宽高、通道、dtype、stride/pitch、ROI、值域
算法：边界、坐标映射、滤波核、舍入/饱和、精度与库模式
输出：形状、文件格式、字节序、保存目录
CPU/库参考：实现版本、同语义检查、误差定义和阈值
环境：附录 E 模板；其他负载/功率限制/MIG/频率条件
```

对图像数据建议保存输入样本、输出预览、局部放大、绝对差图和质量指标配置。若原始数据不能公开，可保存生成脚本和无敏感内容的小规模可复现样本；仍要报告真实测试集的来源、许可/处理约束和统计形状，不把小样本成绩冒充真实数据结果。

| 变体/规模 | 预热 | 重复/独立轮次 | kernel 中位数/p95 | H2D/D2H | 分配/计划/编译 | 端到端中位数/p95 | 显式设备缓冲/峰值 |

定义时间边界：kernel event 测量哪几次 launch、是否包含同步和库调用；“任务”时间是否包含 Host 传输；端到端是否包含读写文件、CPU 参考、上下文与计划创建。不同边界不能相除得“加速比”。设备显式 `cudaMalloc` 字节数不等于实际峰值显存，库工作区和上下文仍要计入；若没有可靠峰值工具，明确只报显式分配。共享 GPU 上报告其他负载与测量波动，不选择性挑最快一次。

## F.4 结论与后续假设

```text
观察到的效果：在哪些已测输入上，哪条路径较快/较慢；数字与误差。
可解释证据：时间线、SASS、寄存器/共享内存、内存吞吐、缓存等。
限制：样本数、输入代表性、单卡/双卡/多节点、工具缺失、统计不确定性。
待检验假设：下一次只改一个因素，例如 tile 大小、batch、传输方式。
回退条件：优化路径不支持的设备/形状/精度与通用路径的行为。
```

一张小图或一次矩阵乘的 `kernel_ms` 不能证明方案在项目场景中更优。完整项目优先量端到端延迟/吞吐、输出质量、资源成本和可复现性；对吞吐任务还应报告 batch、并发数和尾延迟。
