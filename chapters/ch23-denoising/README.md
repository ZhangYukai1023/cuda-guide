# 第 23 章：去噪算法与质量评价

[全书导航](../../README.md) · [原始大纲](../../outline.md) · [上一章](../ch22-mean-gaussian/README.md)

前一章比较了邻域读取方法，本章比较去噪方法本身。示例 [denoising.cu](examples/denoising.cu) 从一张有明暗边界和方格纹理的 64×64 干净图出发，以固定种子造椒盐与高斯噪声；对每种噪声分别运行 3×3 中值、5×5 高斯、5×5 双边滤波。输出保留输入、处理图、局部放大、相对干净图的绝对差异图以及 PSNR/SSIM8 和时间。六条 GPU 路径已在 zyk 编译并通过 CPU 对照；生成的 PGM 也通过可选输入路径。

## 1. 先确认噪声和质量目标

椒盐噪声把约 3.5% 像素改为 0、约 3.5% 改为 255；位置由 `seed=20260928` 的整数混合函数确定。高斯噪声由同一种子生成的均匀数经 Box–Muller 变换得到，标准差为 18 个 8 位灰度级，最后四舍五入并饱和到 `[0,255]`。输入在 CPU 上一次生成，CPU 与 GPU 滤波使用**完全相同的有噪图**，不会各自重新抽样。跨语言或不同数学库重做高斯噪声时，超越函数舍入可能略异；比较结果以保存的 PGM 字节为准。

PSNR 从干净参考与候选图的 MSE 计算，动态范围取 255，MSE 为零时报告无穷大。本例 `SSIM8` 是**非重叠 8×8 窗口**的 SSIM 均值：每窗计算亮度均值、总体方差与协方差，常数 `C1=(0.01*255)^2`、`C2=(0.03*255)^2`。它固定窗口且没有高斯加权；不能把此数值直接与其它库的默认 SSIM 实现比较。有干净参考时这两个指标有解释力；真实图像若没有干净参考，不能用有噪图冒充 ground truth。PSNR/SSIM8 应结合边界与纹理局部图观察，高分不自动等于更好的视觉质量。

## 2. 三种滤波的计算约定

中值滤波把 3×3 邻域九个 8 位值排序，取第五个，常用于去掉孤立极值。高斯滤波复用第 22 章的 `[1,4,6,4,1]` 外积，权重和 256，只在最终做一次整数舍入；它会平滑局部变化，也可能模糊边缘。双边滤波同时考虑空间距离与中心像素灰度差，权重为

```text
exp(-(dx²+dy²)/(2*1.4²)) * exp(-(neighbor-center)²/(2*32²))
```

窗口半径为 2。CPU 先生成 25 个空间权重和 256 个灰度差权重，GPU 将两张表放入常量内存；输出为加权和除以权重和，再四舍五入。中心像素权重为 1，故分母不为零。双边滤波可能保留强边界，也可能使细纹理或噪声残留，效果取决于空间/值域参数。本例只对每张图运行一组参数，不能宣称双边滤波总是更优。NLM 属于进阶方法：它比较一片 patch 与其它位置的 patch 而非只比较单像素；搜索窗和 patch 增大时工作量明显增加，需另设明确的边界、权重与性能实验。

所有滤波采用**复制边界**，不对输入原地写回。CPU 中值用标准排序，GPU 用插入排序；算法不同但第 5 个值应完全相同。CPU/GPU 高斯要求逐字节一致。双边浮点累计在不同指令融合和舍入下允许最多 1 灰度级误差，程序打印最大误差以及超过容差的像素数；若超过 1 则失败。质量指标根据**GPU 输出**计算，CPU 对照误差另列，二者不能混为一个指标。

## 3. 构建与复现

仓库已包含公共 `chapters/common/image_io.hpp`。在仓库根目录执行：

```bash
cmake -S chapters/ch23-denoising/examples -B build/ch23 \
  -DCMAKE_CUDA_COMPILER=/home/zhangyukai/.local/cuda/bin/nvcc \
  -DCMAKE_CUDA_ARCHITECTURES=120 -DCMAKE_BUILD_TYPE=Release
cmake --build build/ch23 -j
ctest --test-dir build/ch23 --output-on-failure
./build/ch23/denoising build/ch23/manual-images
```

也可传入一张自己的**8 位 P5、恰好 64×64**干净灰度参考图，程序按相同种子与参数在其上造噪并对照：

```bash
./build/ch23/denoising build/ch23/user-images /path/to/clean-64x64.pgm
```

程序打印两条有噪输入质量和六条滤波记录，后者都需 `beyond_tolerance=0 ... PASS`，末尾为 `chapter 23 denoising: PASS`。每种输出的 `-diff.pgm` 是与干净图的绝对误差，**不是** CPU/GPU 差异；`-edge-zoom.pgm` 将 `(24,24)` 到 `(39,39)` 的 16×16 区域用最近邻放大 8 倍，跨越明暗边界。应并排看原图、噪声、输出、局部和差异图。`kernel_ms` 是一次内核的 CUDA Event 时间；`task_ms` 包含 H2D、D2H、初始化和同步，但不含图像读写、CPU 参考和缓冲申请。单次值仅供观察，公平性能比较须预热、重复、多次采样并记录设备负载。

## 4. 参数与故障实验

把椒盐发生率从约 7% 增到 20%，再次观察中值滤波是否仍能恢复细线；把高斯标准差从 18 提高，检查高斯滤波的 PSNR 和边缘变化；把双边的值域 `sigma_range=32` 分别改小或改大，观察噪声残留与边缘模糊。**每次只改一个参数**，保留同一干净参考及种子，并记录输入质量、输出质量和时间。若想把中值窗口增到 5×5，需要选择第 13 个排序值并明确更大窗口的边界处理，GPU 局部数组与比较成本也会上升。

常见错误：

- CPU 和 GPU 分别生成噪声，输入不同却比较输出误差。
- 只报告“滤波后 PSNR”，没有保存原始有噪图与基线分数。
- 把没有干净参考的真实图像直接用于 PSNR/SSIM。
- 双边滤波没有归一化权重，或把灰度差作为带符号下标访问查表。
- 浮点双边结果硬性要求所有平台位级相等，或反过来给过大的容差掩盖索引故障。
- 只看整图缩略图，忽略边缘附近细节和差异图。
- 把单次 Event 时间等同于完整批量任务的吞吐。

## 5. 练习与参考答案

1. 3×3 邻域排序后为 `[0,40,41,42,43,44,45,46,255]`，中值是多少？答：第五项 43，两个孤立极值不会直接决定输出。
2. 干净图与输出完全相同时 PSNR 是多少？答：MSE 为零，PSNR 记作正无穷；它不表示算法时间或实际场景质量无限好。
3. 双边中心像素是否可能使分母为零？答：本章空间/值域指数权重的中心项为 1，因此不会。
4. 增大 `sigma_range` 到很大时，双边更接近哪种滤波？答：灰度差抑制减弱，趋近仅按空间距离加权的高斯式平滑。
5. 为什么同一输出的 `-diff.pgm` 不等于 CPU/GPU 差异图？答：它比较的是 GPU 输出与**干净参考**，衡量去噪残差；CPU/GPU 正确性用程序中的 `CPU_max_error` 与 `beyond_tolerance` 判断。
