# 第 24 章：插值、缩放与几何重采样

[全书导航](../../README.md) · [原始大纲](../../outline.md) · [上一章](../ch23-denoising/README.md)

缩放与旋转采用**逆向映射**：每个目标像素找到源图中的采样坐标，而不是把源像素向目标图撒点。示例 [image_resampling.cu](examples/image_resampling.cu) 用 4×4 手算图比较最近邻、双线性、Catmull–Rom 双三次，再用 8×8 棋盘格比较最近邻与面积缩小，最后复用采样函数做 90° 旋转。每个 GPU 结果和 CPU 对照比较并输出 PGM 与差异图。十条默认重采样路径和可选 PGM 双线性放大已在 zyk 编译并通过 GPU/CPU 对照。

## 1. 坐标、边界与取整约定

缩放采用半像素中心映射：

```text
sx = (x_dst + 0.5) * source_width  / target_width  - 0.5
sy = (y_dst + 0.5) * source_height / target_height - 0.5
```

整数坐标表示像素中心。最近邻选择 `floor(s+0.5)`；双线性从 `floor(sx),floor(sy)` 的四个邻居按小数部分加权；双三次用 `a=-0.5` 的 Catmull–Rom 核，各方向四个样本，共 16 次访问。图外坐标按**复制边界**夹到最靠近的有效像素。浮点插值结果以 `floor(v+0.5)` 四舍五入并饱和到 8 位。双三次核可能过冲到 `[0,255]` 外，所以饱和步骤尤其必要。这里处理编码后的 8 位灰度值，不做 sRGB 到线性光转换。

输入 4×4 小图各行是：

```text
 20  37  54  71
 63  80  97 114
106 123 140 157
149 166 183 200
```

放大为 7×5 时，目标中心 `(3,2)` 对应源坐标 `(1.5,1.5)`：最近邻取源 `(2,2)` 为 140；双线性取 `80,97,123,140` 的均值为 110。程序先用这两个手算断言核对 CPU 坐标实现，再运行 GPU。若改成“角点对齐”公式 `x_dst*(source_width-1)/(target_width-1)`，内点坐标会不同，与其它库逐像素比较时必须先核对开关与边界模式，不能凭算法名称推断相同。

90° 旋转是逆仿射映射的一例：在本章 4×4 方图上，目标 `(x,y)` 读取源 `(y,3-x)`，并复用双线性采样。四角期望依次为左上 149、右上 20、左下 200、右下 71，程序有手算断言。推广到任意角度时应为每个目标坐标计算逆矩阵，再交给同一采样函数；目标画布大小和图外填充值也要明确。这里的 90° 示范不代表任意旋转已经实现。

## 2. 缩小与抗混叠

棋盘格在较粗的目标网格上可能被最近邻采成不规则明暗块，这是采样混叠。面积路径把每个目标像素对应的源矩形与源像素格求交，按重叠面积加权平均，再统一舍入。8×8 → 3×3 的尺寸比不是整数，因此必须处理部分覆盖像素。面积缩小相当于一种低通预滤波；它与专门设计的 Lanczos 等滤波器并非同一核。示例另用常量 5×3 图检验四种采样方式在 7×5 输出上都保持 73，排除边缘归一化错误。`AREA` 的教学实现按覆盖源像素循环，适合本例缩小；大比例缩小或批量图像应考虑分阶段滤波、积分图或成熟图像库。

## 3. 构建、运行与对照

仓库已包含公共 `chapters/common/image_io.hpp`。在仓库根目录执行：

```bash
cmake -S chapters/ch24-image-resampling/examples -B build/ch24 \
  -DCMAKE_CUDA_COMPILER=/home/zhangyukai/.local/cuda/bin/nvcc \
  -DCMAKE_CUDA_ARCHITECTURES=120 -DCMAKE_BUILD_TYPE=Release
cmake --build build/ch24 -j
ctest --test-dir build/ch24 --output-on-failure
./build/ch24/image_resampling build/ch24/manual-images
```

还可传一张 8 位 P5 灰度图（宽高各不超过 2048），作双线性 2 倍放大：

```bash
./build/ch24/image_resampling build/ch24/user-images /path/to/input.pgm
```

程序打印每种转换的 `max_error`、`beyond_tolerance`、单次 `kernel_ms` 和含 H2D/D2H 的 `task_ms`；正确性要求 `beyond_tolerance=0`，末尾打印 `chapter 24 image resampling: PASS`。最近邻、90° 旋转与常量保持要求精确一致；双线性、双三次、面积路径允许至多 1 灰度级的 CPU/GPU 浮点舍入差。PGM 输出旁的 `-diff.pgm` 是 CPU/GPU 绝对差异，16×16 以内的图另有 `-zoom.pgm` 最近邻放大 16 倍。特别检查首末行列、4×4 中心位置和棋盘格结果；自然图需同时查看放大区域与细线、边缘。单次计时不能用于性能排名，真实比较应预热、重复并控制输入尺寸与设备负载。

使用 NPP 或 OpenCV 对照时，先匹配像素中心、边界、插值核参数、数据类型和取整规则；不同默认值的结果无需逐字节相等。纹理对象是可选进阶路径，可对照硬件采样和缓存行为，但其坐标与滤波精度约定也要独立核查。参考 [NPP 几何变换文档](https://docs.nvidia.com/cuda/npp/image_geometry_transforms.html)及 [OpenCV 几何变换文档](https://docs.opencv.org/4.x/da/d54/group__imgproc__transform.html)。

## 4. 常见错误

- 用正向映射直接写目标，目标坐标被多源像素覆盖或留下空洞。
- 忘记 `+0.5/-0.5`，得到半像素错位，图像内部似乎接近但边缘不一致。
- 把坐标先截成整数再做双线性，结果退化为近邻。
- 双三次结果没做饱和，过冲后转换成无符号字节会回绕。
- 对缩小棋盘格只用近邻，却把混叠解释成 GPU bug。
- CPU 和 GPU 对照采用不同边界或取整；只比较内部像素，不验证边缘。
- 对大缩小比例直接让每个输出线程扫描大量源像素，却从一个小样本推断性能。

## 5. 练习与参考答案

1. 4×4 → 7×5 的目标中心 `(3,2)` 对应哪个源坐标？答：`(1.5,1.5)`；本章最近邻输出 140，双线性输出 110。
2. 常量图 73 经双三次后边界应是多少？答：仍应为 73（本章复制边界与权重归一约定）；若不是，先查边界采样与权重和。
3. 本章 90° 旋转的目标 `(0,0)` 读取源哪里？答：源 `(0,3)`，值 149。
4. 为什么 8×8 棋盘格缩到 3×3 更适合面积路径？答：目标像素覆盖多个源像素且边界多为非整数，面积加权能平均高频变化；最近邻只选一个点，容易混叠。
5. NPP 双线性与本章逐字节不同就代表谁错了吗？答：不一定；先比对坐标、边界、滤波与量化规则，再用同语义 CPU 参考判定。
