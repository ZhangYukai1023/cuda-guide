# 第 25 章：边缘、形态学与对比度增强

[全书导航](../../README.md) · [原始大纲](../../outline.md) · [上一章](../ch24-image-resampling/README.md)

本章把图像计算分成三类：Sobel 是逐输出像素的邻域计算；膨胀、腐蚀以及开闭运算需要邻域并在多阶段之间保留顺序；直方图均衡化需要先全局统计，再由前缀和生成映射表。示例 [image_features.cu](examples/image_features.cu) 包含每条路径的 CPU 参考、GPU 实现、PGM 输出、局部放大与 CPU/GPU 差异图。三种尺寸各六条默认路径已在 zyk 编译并通过 GPU/CPU 逐字节对照；可选 PGM 输入也通过。

## 1. Sobel 梯度

本例分别使用下列 3×3 相关核，图外像素按零处理：

```text
Gx = [-1  0  1;  -2  0  2;  -1  0  1]
Gy = [-1 -2 -1;   0  0  0;   1  2  1]
```

输出是 `min(255, |Gx|+|Gy|)` 的 8 位灰度图。这是便于手算的 L1 梯度幅值，和 `sqrt(Gx²+Gy²)` 的欧氏幅值、不同缩放或边界规则的库结果不同。5×5 小图是暗背景上的 3×3 灰块，中心像素 200，周围八点 50。中心 `(2,2)` 对称，`Gx=Gy=0`；程序先断言此手算性质，再检查完整 CPU/GPU 图。边界外零填充会在图边缘产生响应，这是明确约定，不是内核越界。

## 2. 形态学与结构元素

输入先以 `v>=128` 二值化。膨胀取以目标像素为中心 3×3 **全一方形结构元素**内的最大值；腐蚀取最小值，图外按 0。开运算是先腐蚀后膨胀，通常能去除小的亮孤点；闭运算是先膨胀后腐蚀，常用于填补小暗洞。程序为两个阶段使用单独设备中间缓冲，不原地覆盖输入，也不假定 Block 之间可在一个普通 kernel 中全局同步。3×3 单个中心亮点的膨胀使九个位置变亮，是第二个手算断言。

结构元素若改成十字，只检查中心与四个轴向邻居，斜角的结果可能不同；不能仍用方形的 CPU 参考。零填充对腐蚀尤其有影响：贴近图边的亮区域可能被图外零值削掉。本章没有额外的“忽略图外”模式，使用库函数对照时先核对其边界约定。

## 3. 直方图、前缀和与均衡化

GPU 先用 `atomicAdd` 统计 256 个灰度箱；直方图清零后，每个输入像素贡献一个计数。教学版 LUT kernel 用**一个线程**顺序扫描 256 个箱得到累计分布 `cdf`；这样容易检查语义，生产代码可用第 8、11 章的并行 Scan 或成熟库替代。把首个非空箱的累计数记为 `cdf_min`，映射公式为

```text
lut[v] = round((cdf[v] - cdf_min) * 255 / (N - cdf_min))
```

对 `cdf[v] <= cdf_min` 设为 0。若整张图只有一个灰度值，则分母为零；本章约定保持原图不变。小直方图 `[0,0,128,255]` 的输出仍为 `[0,0,128,255]`，程序有手算断言。此映射会改变灰度分布与整体对比度，不一定改善所有图像；若原图很暗、含大量噪声，均衡化也可能放大噪声。彩色图像若分别均衡三个 RGB 通道还可能改变色彩，本例仅处理灰度。

## 4. 构建、运行与检查

仓库已包含公共 `chapters/common/image_io.hpp`。在仓库根目录执行：

```bash
cmake -S chapters/ch25-edges-morphology-contrast/examples -B build/ch25 \
  -DCMAKE_CUDA_COMPILER=/home/zhangyukai/.local/cuda/bin/nvcc \
  -DCMAKE_CUDA_ARCHITECTURES=120 -DCMAKE_BUILD_TYPE=Release
cmake --build build/ch25 -j
ctest --test-dir build/ch25 --output-on-failure
./build/ch25/image_features build/ch25/manual-images
```

可选地传入一张 8 位二进制 P5 灰度图（宽高各不超过 2048）：

```bash
./build/ch25/image_features build/ch25/user-images /path/to/input.pgm
```

默认运行 5×5 手算图、7×9 常量图以及 257×193 非整齐中图。每张都执行 Sobel、膨胀、腐蚀、开、闭、均衡化，程序打印 `mismatches=0 ... PASS`，最后打印 `chapter 25 image features: PASS`。`*-diff.pgm` 是 GPU 与 CPU 的绝对差，较小图另保存 `*-zoom.pgm` 最近邻放大 16 倍。GPU 的两阶段开闭路径必须与 CPU 的同序两阶段结果逐字节相同；直方图/LUT 路径也要求精确相同。图像保存时间不计入 `task_ms`；单次 `kernel_ms` 包含本算法相关的设备 kernel 序列，均衡化的计时还包含清零。性能比较需预热并重复运行，分别看邻域访问、原子争用和扫描阶段，不能把本章一次观察当作结论。

## 5. 常见错误

- Sobel 核方向和灰度梯度符号约定不清，却把符号差异写成错误；本章输出是绝对值之和。
- `abs` 前先把有符号梯度转成 `uint8_t`，造成回绕。
- 膨胀/腐蚀忘记图外零值，或把二值阈值 `>=128` 写成 `>128`。
- 开闭运算的顺序颠倒，或把输入、输出指向同一缓冲，导致读取到部分新值。
- 直方图未清零、箱计数用普通 `++`，或映射前没有等待 LUT 生成。
- 常量图的 `N-cdf_min=0` 未处理，出现除零或不可预期输出。
- 只看均衡化后的图“更亮”，没有核对映射表和细节是否丢失。

## 6. 练习与参考答案

1. 本章 Sobel 在 5×5 小图中心 `(2,2)` 的输出是多少？答：左右、上下对称，`Gx=Gy=0`，输出 0。
2. 只有一个亮点的 3×3 二值图，3×3 方形膨胀后的九个像素是什么？答：全部 255；十字结构元素则只有中心与四个轴向邻居变亮。
3. 为什么开、闭需要两个 kernel？答：第二步依赖第一步的整张中间图；普通不同 Block 没有全局同步，另一次 kernel 提交提供阶段边界。
4. `[0,0,128,255]` 的 `cdf_min` 是多少？答：首个非空灰度 0 的累计数为 2；总数 4，128 映射为约 128，255 映射为 255。
5. 常量图 `73` 怎样处理均衡化？答：`N-cdf_min=0` 时按本章接口约定输出仍为 73，不执行除法。
