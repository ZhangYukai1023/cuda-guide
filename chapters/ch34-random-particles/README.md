# 第 34 章：随机计算与粒子模拟

[全书导航](../../README.md) · [原始大纲](../../outline.md) · [上一章](../ch33-stencil-heat/README.md)

本章用 [random_particles.cu](examples/random_particles.cu) 运行三个任务：Monte Carlo 圆周率估计、随机积分 `∫₀¹4/(1+x²)dx`、软化后的粒子加速度。前两个任务将每个样本绑定到确定的计数器，CPU 和 GPU 应读到同一批伪随机数；第三个任务比较朴素与共享内存分块 `N`-body 计算，并对照 CPU 双精度参考。本章已在 zyk 使用 nvcc 12.8 独立编译并通过 GPU/CPU 对照，见[验证记录](results/validation.md)。

## 1. 随机样本、种子与统计误差

估计 π：在单位正方形 `[0,1)²` 均匀抽样，落入四分之一单位圆的比例为 `π/4`。设 `I_i` 为命中指示量，`π̂=4ΣI_i/N`。本例固定 `N=2^18`、种子 `20260928`，GPU 先在每个 256 线程块内归约命中数，再对全局计数器做整数 `atomicAdd`。CPU 用同样的样本逐一计数，**命中数必须完全一致**。这检验了索引、抽样、边界判定和归约，胜过只检查 `π̂` 是否“接近 3.14”。

积分使用另一条按域分离的伪随机流，计算 `f(x)=4/(1+x²)`，其真值为 `π`。GPU 块内归约 `f` 与 `f²` 后以双精度原子加写入总和；CPU 按同一计数器序列顺序累加。浮点加法顺序不同，GPU 与 CPU 积分估计允许 `1e-6` 的绝对差，不能要求总和逐 bit 相同。

随机生成器将 `seed+counter` 通过 64 位整数混合，再取高 24 位除以 `2²⁴`，得到 `[0,1)` 中的值。样本取决于**全局样本编号**，与 GPU 线程调度、块数和执行顺序无关；圆周率和积分使用不同的计数器域。它是教学用确定性伪随机映射，不是密码学随机数，也没有替代经过专门统计检验的高质量模拟 RNG。若改用 cuRAND Philox，也应明确 seed、sequence/subsequence、offset 和每样本消耗的随机数数量；只记录一个 seed 不足以复现实验。

**统计误差与实现错误要分开。** 在独立均匀抽样假设下，命中概率 `p≈π/4`，圆周率估计的标准误差可用 `4√[p̂(1-p̂)/N]` 估计；积分的标准误差可用 `√[(mean(f²)-mean(f)²)/N]` 估计。程序同时打印相对真实 π 的偏差与这两个估计的标准误差，但不以“本次是否落在某个置信区间”做确定性通过门槛，因为合格的随机样本也可能偶然偏离。固定样本上的 CPU/GPU 差异才用严格确定性条件判定。要评价 RNG 质量或误差分布，应使用多组独立种子、足够样本和更专门的统计测试。

## 2. 粒子力与数据布局

粒子位置和质量用 `float4(x,y,z,mass)` 的 AoS 布局，一个线程计算一个目标粒子的三维加速度：

```text
d = position[j] - position[i]
a[i] += mass[j] * d / (|d|² + ε²)^(3/2)
```

本章取 `ε²=0.01`，使相近粒子和自身项不会出现除零；自身项的位移为零，所以贡献仍为零。这里只算一次力/加速度，不积分轨道，也未加入引力常数、单位制、周期边界或碰撞。`N=193` 刻意不是 128 的整数倍，检验尾块。GPU 使用 `rsqrtf` 和 FP32 累加，CPU 用输入的同一组 FP32 坐标转双精度求参考；逐分量检查朴素版、分块版相对 CPU 和两版之间的最大差异，阈值设为 `3e-3`，本机样本在 zyk 实测通过。

朴素版本的每个线程遍历全部 `N` 个粒子，重复从全局内存读取。分块版让 128 个线程合作将 128 个 `float4` 装入共享内存，然后各线程使用同一 tile 的粒子；每块内有前后两次 `__syncthreads()`，保证装载完成且上一 tile 不再被读取后才覆盖。尾块中没有目标粒子的线程也必须参加同步，不能提前返回。两个版本均为 `O(N²)` 计算；分块主要减少重复读取，无法改变算法复杂度。对极大 `N`，Barnes–Hut、快速多极子或邻域截断等算法层面的选择可能更重要。

AoS 的 `float4` 让一次访问拿到位置和质量，适合共享 tile；若主要逐字段处理大量粒子，可以另测 SoA 的 `x[]/y[]/z[]/m[]`，并比较合并访存、寄存器和转换成本。实际粒子模拟还需数值积分、守恒量监测和时间步稳定性，本章只覆盖一次相互作用求和。

## 3. 构建、运行与记录

在远程仓库根目录：

```bash
cmake -S chapters/ch34-random-particles/examples -B build/ch34 \
  -DCMAKE_CUDA_COMPILER=/home/zhangyukai/.local/cuda/bin/nvcc \
  -DCMAKE_CUDA_ARCHITECTURES=120 -DCMAKE_BUILD_TYPE=Release
cmake --build build/ch34 -j
ctest --test-dir build/ch34 --output-on-failure
./build/ch34/random_particles
```

输出应包括 GPU 型号、样本数与种子、CPU/GPU 完全相同的命中数、两个 π 估计值与标准误差、同一样本的积分 CPU/GPU 差异，以及 193 粒子的三组最大误差。所有确定性检查通过后才打印 `chapter 34 random and particles: PASS`。本例没有正式性能基准；要比较朴素与分块版本，应在更大且相同的 `N` 下预热、多次 CUDA event 计时，并单独报告 Host/Device 传输、CPU 参考、GPU kernel、总时间。Monte Carlo 统计精度通常以 `O(N^{-1/2})` 改善，样本数加四倍，典型标准误差才约减半；不能用单次 GPU 加速比替代精度报告。

## 4. 常见错误

- 每个线程从相同 seed/状态开始，生成完全相同的样本，误将大量复制样本当作独立试验。
- 用线程号而非全局样本编号定义随机流，改动网格后结果不可复现；或圆周率和积分无意使用重叠计数器域。
- 把 `|π̂-π|` 当成每次必须低于固定小阈值的程序正确性测试，误判正常抽样波动。
- 对浮点原子归约要求逐 bit 与 CPU 顺序求和相同；也不能借此忽略大幅超出舍入误差的错误。
- `N`-body 忘记软化，重合粒子/自身项出现 Inf/NaN；或 CPU/GPU 的软化常数不一致。
- 分块版尾块的空线程提前 `return`，使其余线程卡在 `__syncthreads()`；未等待上个 tile 读完就覆盖共享数据。
- 用 193 粒子的单次运行声称共享内存一定更快，忽略启动成本与 `O(N²)` 增长。

## 5. 练习与参考答案

1. 固定命中概率下，若希望 Monte Carlo 标准误差约降为原来一半，需要多少倍样本？答：四倍，因为标准误差与 `1/√N` 成正比。
2. 同一 seed 下改了线程块大小，当前计数器 RNG 的圆周率命中数应变化吗？答：不应变化；每个全局样本编号仍取同两个计数器。浮点总和低位可能因归约顺序改变。
3. 为什么 `π̂=3.12` 不能单独证明 kernel 算错？答：估计值有统计波动；应先看样本数和标准误差，再用相同样本 CPU 参考精确比较命中数。
4. 193 粒子、tile 大小 128 时，第二个 tile 有多少有效粒子？答：65 个；其余装载位置应安全填充且线程继续参加同步。
5. `ε²` 从 0.01 改到 0 后还可以用同一验收参考吗？答：不可以。模型和数值奇异性都变了，需要重新定义对重合/自身项的处理和 CPU 对照。
