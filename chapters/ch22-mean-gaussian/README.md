# 第 22 章：从均值滤波到高斯滤波

[全书导航](../../README.md) · [原始大纲](../../outline.md) · [上一章](../ch21-image-layout/README.md)

第 21 章确定单个像素的地址，本章让一个输出像素读取邻域。完整示例 [mean_gaussian.cu](examples/mean_gaussian.cu) 对比 3×3 均值、5×5 离散高斯、两遍可分离高斯和共享内存 Halo。每条 GPU 路径都和独立 CPU 参考逐字节比较，包含行填充。示例已在 zyk 编译；三种尺寸、六条路径共 18 组均与 CPU 参考逐字节一致。

## 1. 从 5×5 小图手算

示例的小图首三行是：

```text
  0  32  64  96  52
 66  60 130 124 118
132 164 120 152 184
```

以位置 `(1,1)` 为中心，3×3 和为 `768`，均值按 `(sum+4)/9` 四舍五入，结果是 `85`。这组对称均值权重既可称卷积也可称相关；对不对称权重，本书示例的实现是**相关**（按 `weight[ky][kx]` 直接乘 `input[y+ky][x+kx]`），数学卷积需先翻转核方向。边界外取值也必须写成契约：左上角在零填充时和为 158，输出 18；复制边界时和为 256，输出 28；`reflect101` 不重复边缘像素，和为 436，输出 48。三种结果不同，并非某一实现必然错误。

5×5 高斯使用一维权重 `[1,4,6,4,1]`，二维权重为外积，归一化分母 256。直接二维版本每像素读取 25 个值。可分离版本先沿水平方向累加到 `int` 中间缓冲，再沿垂直方向累加，**只在最后除以 256 并舍入一次**。若第一遍就转回 8 位，两条路径会有额外量化差异。示例的 CPU 参考和 GPU 都采用同一个整数公式，因此预期逐字节相等。

## 2. 朴素实现、Halo 与同步

`mean3_direct` 每个输出线程读自己的九个邻居，简单且适合作为对照。`mean3_shared_replicate` 每个 16×16 Block 先协作装入 18×18 共享内存 tile：中间 16×16 是输出区域，四周一圈是 Halo。循环让部分线程补齐右侧、下侧及角落，再由**所有线程**执行 `__syncthreads()`，最后才让图像范围外的线程返回。若把边界 return 放到屏障前，部分线程缺席会破坏同步；若漏读 Halo，边缘会出现块状条纹。Shared Memory 只实现复制边界 3×3 均值，避免把不同边界约定混进性能比较。

5×5 高斯两遍路径让中间缓冲留在 GPU；只对最终图像做下载。CPU 参考使用相同边界函数，5×5 小图、17×19 非整齐尺寸、513×257 较大尺寸都验证。例子保留 `stride > width` 的哨兵字节。原地把输入和输出设为同一缓冲会使邻居读到已经修改的值，本章始终分配独立输出；两遍高斯还有单独的 `int` 中间缓冲。

## 3. 构建、运行与观察

仓库已包含 `chapters/common/image_io.hpp`。在仓库根目录执行：

```bash
cmake -S chapters/ch22-mean-gaussian/examples -B build/ch22 \
  -DCMAKE_CUDA_COMPILER=/home/zhangyukai/.local/cuda/bin/nvcc \
  -DCMAKE_CUDA_ARCHITECTURES=120 -DCMAKE_BUILD_TYPE=Release
cmake --build build/ch22 -j
ctest --test-dir build/ch22 --output-on-failure
./build/ch22/mean_gaussian build/ch22/manual-images
```

程序对每个尺寸打印六条 `mismatches=0 PASS`（三种边界均值、直接高斯、可分离高斯、共享内存均值），末尾打印 `chapter 22 mean and Gaussian: PASS`。5×5 输入和各输出保存为 PGM，每个输出另有绝对差异图 `*-diff.pgm`；全部对照通过时差异图为黑色。可用图像工具对小图做最近邻放大，检查左上角和块边界。较大尺寸只输出统计，避免把大量临时图像误提交。

每条路径打印一次 `kernel_ms`（CUDA Event 包围本次内核序列）和 `task_ms`（主机时钟，从 H2D 到 D2H，包含哨兵初始化、Event 操作与同步，不含分配、CPU 参考、文件读写）。这是**单次教学观察，不是可信性能排名**。在 zyk 实测后应预热并重复采样，固定尺寸、边界、输入、架构和其它 GPU 负载；比较 Shared Memory 与朴素访问时还应看访存量和 Occupancy。两遍高斯减少乘加/读取的理论数量，却增加中间缓冲和第二次启动，在小图上未必更快。改变半径时共享内存 tile 与 Halo 比例也变，不能外推固定结果。

## 4. 常见错误

- 忘记说明零填充、复制或反射边界，导致边缘误差被误判为算法故障。
- 把相关实现误称数学卷积，尤其在不对称导数核上得到反向响应。
- 可分离第一遍先截断到 8 位，却要求与只舍入一次的直接卷积逐字节一致。
- Halo 少载一角、`__syncthreads()` 之前提前 return，或 tile 尺寸只留 16×16。
- 把 stride 当宽度、把行填充写成像素，或直接对输入原地写回。
- 只比较中心像素，忽略外边界、非整齐尺寸和跨 Block 的位置。
- 比较一次极短 Event 时间就断言一种实现更快；先定义计时范围并复测。

## 5. 练习与参考答案

1. 首三行小图位置 `(1,1)` 的均值为什么是 85？答：九个像素之和 768，`(768+4)/9=85`（整数除法）。
2. 左上角三个边界策略为何输出 18、28、48？答：零填充、复制和 `reflect101` 对越界九个采样位置映射不同；对应的和分别为 158、256、436，按同一公式舍入。
3. 16×16 输出 tile 的 3×3 滤波至少需多大的输入 tile？答：18×18，四边各多一像素；包括四个角的 Halo。
4. 可分离高斯中间缓冲为何用 `int`？答：水平加权和最大为 `16*255=4080`，8 位放不下；提前量化还会改变最终结果。
5. 哪种路径对 513×257 必然更快？答：仅凭代码不能确定；在相同边界和任务范围下预热、重复测量，并查看实际设备上的内存与计算瓶颈。
